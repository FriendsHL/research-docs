## 📌 第一部分：核心概念与架构（必问）

### ❓ Q1: 请简述 Agent 的基本架构组成，并解释其与传统 LLM Chain 的区别

**答案要点：**
- **Agent = LLM + 规划(Planning) + 记忆(Memory) + 工具使用(Tool Use)**
- **Chain**: 预定义的、线性的硬编码工作流
- **Agent**: 具备"自主性"，根据目标自发决定执行路径，通过推理循环不断调整策略

---

### ❓ Q2: 解释 ReAct 模式的工作原理

**答案要点：**
- **ReAct (Reasoning + Acting)** 是 Agent 的基石
- 将"思考"(Thought)和"行动"(Action)结合
- LLM 先生成一段推理，说明下一步要做什么
- 然后调用工具观察（Observation）结果
- 再根据结果进入下一轮推理

**实战效果**：相比 CoT，复杂问题分解效果更好，准确率提升约 15%

---

### ❓ Q3: 如何实现 Agent 的长期记忆（Long-term Memory）？

**答案要点：**
1. **短期记忆**：利用 Context Window，存储当前会话的历史
2. **长期记忆**：通过 RAG，将历史经验、知识编码为 Embedding 存入向量数据库
3. **2026 新趋势**：
   - 利用长文本模型（Long-context LLMs）直接处理超长历史
   - 通过"摘要层级结构"对记忆进行递归压缩

## 📌 第二部分：多智能体协同（Multi-Agent）

### ❓ Q4: 单 Agent 遇到瓶颈时，为什么需要 Multi-Agent？常见的协作模式有哪些？

**答案要点：**

**为什么需要**：
- 单个 Agent 处理复杂、跨领域长任务时容易出现"注意力漂移"或"推理链断裂"

**协作模式**：
1. **中心化（Boss-Worker）**：一个主 Agent 拆分任务并指派给子 Agent
2. **流水线（Pipeline/Sequential）**：A 的输出作为 B 的输入（如代码生成 → 代码审查 → 修复）
3. **民主协作（Joint Discussion）**：多个 Agent 共同讨论得出结论

---

### ❓ Q5: 多智能体系统中如何解决"无限循环"或"通信冗余"问题？

**答案要点：**
- **循环检测**：引入状态机控制流程，设置最大迭代次数
- **Token 控制**：对 Agent 间的对话进行摘要处理
- **终止条件**：明确定义任务完成的标准（Definition of Done）

## 📌 第三部分：Agent 核心设计模式

### ❓ Q6: 请对比"工作流（Workflows）"与"自主智能体（Autonomous Agents）"的优劣

**答案要点：**

| 模式 | 优点 | 缺点 | 适用场景 |
|------|------|------|----------|
| **Workflows** | 高可靠性、结果可预期 | 灵活性差 | 报销审批、标准化客服 |
| **Autonomous Agents** | 灵活性极高 | 不可预测 | 开放研究、代码编写 |

**2026 工程趋势**："用 Workflow 约束 Agent"，即在框架定义的路径内给予 Agent 局部决策权

---

### ❓ Q7: 详细解释"编排者-执行者（Orchestrator-Workers）"模式

**答案要点：**
- 主 Agent（Orchestrator）负责将复杂任务分解为子任务
- 分发给具有不同 Skill 的 Worker Agents
- 最后汇总结果

**适用场景**：大型软件开发（一个写 UI，一个写后端，一个写测试）

**难点**：任务分解的粒度。拆太细通信成本高；太粗 Worker 会产生幻觉

---

### ❓ Q8: 什么是"反思/自我纠正（Reflection/Self-Correction）"模式？

**答案要点：**
- 提升 Agent 成功率最有效的模式
- Agent 生成输出后，由另一个 Agent 扮演批评者（Critic）
- 检查输出是否符合约束条件，提供反馈让前者迭代
- 可使用 **Reflexion 架构**，记录"失败轨迹"作为长短期记忆，避免重复同样错误

## 📌 第四部分：深度技术实现与状态管理（高频！）

### ❓ Q9: 在多轮对话 Agent 中，如何处理"状态爆炸"和"上下文溢出"？

**答案要点：**

1. **State Schema**：定义严格的状态结构（如使用 LangGraph 的 TypedDict），只保存核心变量
2. **Trim Strategy**：根据语义重要性保留（保留 System Prompt + 最近 N 轮对话 + 当前任务目标）
3. **Summary Buffer**：将旧的对话摘要化，将摘要存入 Context 头部

---

### ❓ Q10: 如何保证 Agent 调用工具（Function Calling）的可靠性？

**答案要点：**

1. **语法层面**：利用 JSON Mode 或强类型约束
2. **逻辑层面**：引入"确认机制（Human-in-the-loop）"，对于高风险操作必须由人点击确认
3. **重试逻辑**：如果 LLM 生成的参数不合法，将报错信息返回给 LLM，让其自我修复（Self-heal）

---

### ❓ Q11: LangGraph 中的"节点（Node）"和"边（Edge）"与传统工作流有何不同？

**答案要点：**

- 传统工作流的边是**固定**的
- LangGraph 的边可以是**条件边（Conditional Edges）**，由 LLM 的输出决定下一步走向哪个 Node
- **支持循环（Cycles）**，这是 Agent 能够不断尝试直到成功的核心

## 📌 第五部分：2026 必考的 Evals（评估）

### ❓ Q12: 你如何量化一个 Agent 的性能？

**答案要点：**

1. **任务成功率 (Success Rate)**：这是核心指标
2. **平均推理步数 (Avg Steps)**：步数越少，成本越低，响应越快
3. **工具调用准确率 (Tool Call Accuracy)**
4. **影子测试 (Shadow Testing)**：在生产环境并行跑新旧 Agent 逻辑，对比输出差异

## 📌 第六部分：Agentic RAG 专项问答

### ❓ Q13: RAG 系统中经常遇到检索出来的片段（Chunk）互相冲突，Agent 该听谁的？

**答案要点：**
1. **元数据加权**：根据文档的实时性、权威性进行权重排序
2. **多智能体辩论（Multi-Agent Debate）**：让不同的 Agent 持不同的 Chunk 进行对比
3. **引用溯源**：强制要求输出必须附带 Source 链接

---

### ❓ Q14: 如何处理企业知识库中的"权限隔离"问题？

**答案要点：**
- **核心策略**：RAG 权限对齐
- 在向量数据库中，每个 Embedding 向量都附带 ACL（访问控制列表）元数据
- 在 Agent 触发检索请求时，强制将"当前用户信息"作为 Filter 注入检索语句中
- **确保在向量检索阶段就完成物理隔离**

---

### ❓ Q15: 当知识库内容更新很快时，RAG 系统如何应对？

**答案要点：**
1. **动态路由**：Agent 根据问题类型识别"实时性要求"，优先调用实时 API
2. **流式索引更新**：利用 Kafka 监听知识库变化，实现增量 Embedding
3. **缓存失效策略**：针对高频问题设置 TTL 缓存，源数据更新时触发失效

---

### ❓ Q16: 如何提升问答准确度

**答案要点：**

**1. 深度解析层：Layout-Aware Parsing**
- 使用 DocLayout-YOLO 或 Unstructured
- 语义分块：按标题层级（H1-H4）切分

**2. 检索增强层：Multi-Stage Retrieval**
- 混合检索：向量检索 + BM25
- 重排序（Reranking）：BGE-Reranker
- 查询扩展：生成 3 个同义问题并行检索

**3. 生成校验层：Self-Correction**
- 验证节点：判断检索内容是否足以回答问题

---

### ❓ Q17: 回答中如何包含原文档相关的图和表格

**答案要点：**

**表格**：解析为 Markdown 格式，为表格生成摘要存入向量库

**图片**：
- 使用多模态模型生成图片描述
- 答案中使用占位符如 `[IMAGE_ID: 123]`，前端解析并渲染

## 📌 第八部分：GitHub 精选面试题（2026年4月新增）

### 一、Multi-Agent 系统深入

#### ❓ Q18: Multi-Agent 比单 Agent 好在哪里？

**答案要点：**
- **单 Agent**：数据量大、工具多，容易"失控"
- **Multi-Agent**：每个 Agent 有特定任务，不会越界，成功率更高
- 可以为不同 Agent 选用不同 LLM 节省成本
- 更好的可维护性和可调试性

---

#### ❓ Q19: 如何管理 Agent 之间的上下文传递？

**答案要点：**
- **Context Drift 问题**：Agent 不知道最初的用户请求是什么
- **解决方案**：维护两种状态
  - **全局状态（Global Context）**：始终传递，保留原始查询
  - **局部状态（Local Context）**：随着信息更新而变化
- **Prompt 注入**：在运行时动态构建指令（原始查询+当前摘要+当前任务）

---

#### ❓ Q20: 如何设计 Agent 的生产级架构？

**答案要点：**
- **异步处理**：用户请求进入 Redis/SQS，返回 202 和 run_id
- **流式响应**：使用 SSE 推送进度（源文档、拉取中、摘要中）
- **状态持久化**：PostgreSQL 存储 checkpoint，无状态容错
- **多队列隔离**：简单查询和复杂查询分开，避免阻塞

---

#### ❓ Q21: Multi-Agent 系统的常见挑战有哪些？

**答案要点：**
1. **不必要的 Agent 调用**：简单查询也走多个子 Agent
2. **任务分解粒度**：拆太细成本高，拆太粗子 Agent 会幻觉
3. **工具选择错误**：Agent 用错工具后才发现上下文不对
4. **MCP 服务器问题**：工具多但描述模糊
5. **错误累积**：Agent 间传递错误会放大
6. **重启恢复**：需要从 checkpoint 恢复，而不是从头开始

---

### 二、Guardrails（防护机制）

#### ❓ Q22: Agent 的安全护栏有哪些？

**答案要点：**
1. **循环控制**：设置 `recursion_limit` 和 `max_steps`，强制终止
2. **工具授权**：限制 API Keys、Root 访问等高风险工具
3. **误操作防护**：如群发 10k 邮件时添加人工确认
4. **Schema 验证**：使用 Pydantic 确保数据格式正确
5. **隐私保护**：个人信息不要传给 LLM，预先脱敏

---

#### ❓ Q23: 如何避免 Agent 进入无限循环？

**答案要点：**
- 设置重试次数上限（如 3 次）
- 设置最大步数限制
- 检测到循环趋势时重定向到出口路径

---

### 三、成本优化

#### ❓ Q24: 5 种降低 Multi-Agent 成本的方法

**答案要点：**
1. **语义缓存（Semantic Caching）**：相似问题命中缓存，如"如何改密码"类问题
2. **模型分级**：简单任务用小模型，复杂任务用大模型
3. **按需调用 Agent**：简单查询只调用一个 Agent + 多个工具
4. **减少 Token**：优化 Prompt，只保留核心信息
5. **结果复用**：相同/相似问题的中间结果复用

---

### 四、向量数据库与 RAG 深入

#### ❓ Q25: 向量数据库的搜索优化

**答案要点：**
- **HNSW 索引**：将复杂度从 O(n) 降到 O(log n)
- **混合检索**：稀疏向量（BM25）+ 密集向量（Embedding）
- **元数据过滤**：每个向量带元数据，快速筛选
- **重排序（Rerank）**：初筛后用 Cross-Encoder 精排

---

#### ❓ Q26: RAG 评估指标有哪些？

**答案要点：**
1. **答案相关性**：与标准答案对比
2. **幻觉检测**：答案是否在检索到的文档中
3. **检索相关性**：检索的文档是否与用户查询相关
4. **上下文利用率**：使用的上下文片段占总量的比例

### 六、客服 Agent 专项

#### ❓ Q29: 如何处理"复合意图"（如：我想改地址因为账单寄错了）？

**答案要点：**
- **意图优先级**：设置主要意图和次要意图
- **先处理主要意图**：如先处理地址变更
- **主动确认**：完成后询问"接下来处理账单问题吗？"
- 让用户感受到被倾听，不用重复说明

---

#### ❓ Q30: 目标完成率高但 CSAT 低的原因？

**答案要点：**
- **程序性摩擦**：Agent 能解决问题但流程太繁琐
- **重复询问**：让用户重复提供已提供的信息
- **过度验证**：已经验证过的信息又验证一遍

---

### 七、Pydantic 在 AI 系统中的作用

#### ❓ Q31: 为什么生产环境需要 Pydantic？

**答案要点：**
- **数据验证**：确保 LLM 输出是有效的 JSON
- **Schema 验证**：在开发阶段捕获数据类型错误
- **序列化**：自动类型转换（如 '5' → 5）
- **强制结构化输出**：确保输出符合业务要求
- 核心用 Rust 编写，性能极高

### 八、强化学习与训练（来自 GitHub 精选）

#### ❓ Q32: PPO、DPO、GRPO 的区别？

| 算法 | 特点 | 适用场景 |
|------|------|----------|
| **PPO** | 稳定性强，显存占用大 | 复杂任务、对稳定性要求高 |
| **DPO** | 直接优化偏好，无需显式奖励模型 | 偏好数据丰富 |
| **GRPO** | 显存友好，DeepSeek 采用 | 资源受限场景 |

#### ❓ Q33: 什么是损失屏蔽（Retrieved Tokens Loss Masking）？

**答案要点：**
- 在训练时，对 RAG 检索到的内容不计算损失
- 避免模型过度记忆检索内容
- 让模型学会正确使用检索结果而非背诵

---

#### ❓ Q34: LoRA 的核心思想？

**答案要点：**
- 在冻结的预训练权重旁添加低秩矩阵
- 训练时只更新低秩矩阵，显存占用大幅降低
- 推理时可合并回原权重，无额外延迟

### 九、疑难问题（来自 GitHub 精选）

#### ❓ Q35: 灾难性遗忘是什么？如何解决？

**答案要点：**
- **定义**：模型在新任务上表现好，但忘记了原有能力
- **解决方案**：
  - 增量预训练时混合原任务数据
  - 课程学习（从简单到难）
  - 正则化约束关键权重

#### ❓ Q36: 幻觉（Hallucination）如何解决？

**答案要点：**
1. **RAG**：提供真实上下文
2. **置信度校验**：低于阈值时要求确认
3. **事实核查**：引入独立的事实核查模块
4. **人工复核**：关键场景必须人工确认

#### ❓ Q37: 长文本处理有哪些方法？

**答案要点：**
1. **稀疏注意力**：只关注局部关键区域
2. **滑动窗口**：分块处理，跨块保留信息
3. **层级汇总**：从句子→段落→文档逐层压缩
4. **位置编码**：RoPE、ALiBi 等可扩展的位置编码
