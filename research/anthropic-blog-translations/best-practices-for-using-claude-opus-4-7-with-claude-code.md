## 概述

Opus 4.7 是我们迄今为止用于编码、企业工作流和长时间运行的 Agent 任务的**最强大的通用模型**。它比 Opus 4.6 更好地处理歧义，在查找 bug 和审查代码方面更强跨 session 携带上下文更可靠，并且可以用更少的指导推理模糊任务。

在发布公告中，我们注意到两个变化——更新的 tokenizer 和在更高 effort 级别时更多思考的倾向，特别是在更长 session 的后期轮次——影响 token 使用。因此，当用 Opus 4.7 替换 Opus 4.6 时，可能需要一些调整才能达到最佳性能。对 prompt 和 harness 进行一些调整可以产生很大的不同。

---

## 结构化交互式编码 Session

Opus 4.7 的 token 使用和行为可能取决于你是部署更多自主、异步的编码 agent（单个用户 turn）还是更多交互式、同步的编码 agent（多个用户 turn）。在交互设置中，它在用户 turn 后会更多推理：这提高了其在长 session 中的连贯性、指令跟随和编码质量，但也往往会使用更多 token。

### 最佳实践

为了在 Claude Code 中充分利用 Opus 4.7，我们发现将 Claude 更像是一个你委托的有能力的工程师，而不是一个你逐行指导的配对程序员：

1. **在第一个 turn 中 upfront 指定任务**：包含意图、约束、验收标准和相关文件位置的详细任务描述为 Opus 4.7 提供了提供更强输出所需的上下文。模糊的 prompt 在许多 turn 中逐渐传达往往会降低 token 效率，有时还会降低整体质量。

2. **减少所需的用户交互次数**：每个用户 turn 都会增加推理开销。批量你的问题，给模型保持移动所需的上下文。

3. **在适当的时候使用 auto mode**：对于你信任模型可以安全执行而无需频繁检查的任务，auto mode 减少周期时间。它特别适合你已经 upfront 提供完整上下文的长任务。Auto mode 现在对 Claude Code Max 用户以研究预览形式提供——你可以使用 Shift+Tab 切换它。

4. **设置任务完成通知**：要求 Claude 在完成任务时播放声音，它可以创建自己的基于 hook 的通知。

## Opus 4.7 的推荐 Effort 设置

Opus 4.7 在 Claude Code 中的默认 effort 级别现在是 **xhigh**。这是一个新的 effort 级别，在 high 和 max 之间，让用户更好地控制困难问题上推理和延迟之间的权衡。

### 各级别指导

- **medium 和 low**：适用于对成本敏感、延迟敏感或范围狭窄的工作。模型在更高 effort 级别上会更不强，但仍然优于在相同 effort 级别运行的 Opus 4.6——有时使用更少的 token。

- **high**：平衡智能和成本。如果你运行并发 session 或想少花钱而不大幅降低质量，请选择 high。

- **xhigh（默认，推荐）**：大多数编码和 Agent 使用的最佳设置。它有强大的自主性和智能，而不会在长 agent 运行中产生失控的 token 使用。

- **max**：在真正困难的问题上挤出额外性能，但显示递减回报，更容易过度思考。谨慎地将其用于在评估中测试模型的最大天花板，以及极度智能敏感且对成本不敏感的使用。

如果你升级到新模型，我们建议尝试调整 effort，而不只是移植旧设置。你可以在同一任务中切换 effort 级别，以更有效地管理 token 使用和推理。

## 自适应思考

Opus 4.7 不支持固定思考预算的扩展思考。相反，Opus 4.7 提供**自适应思考**（adaptive thinking）。这使得思考在每一步都是可选的，允许模型根据上下文决定何时使用更多思考。它可以快速响应简单查询，在一步不受益于思考时跳过思考，并将思考 tokens 投资于最可能有用的地方。在 agent 运行过程中，这可以累积为更快的响应和更好的用户体验。

自适应思考在这个版本中有意义地改进了——特别是 Opus 4.7 不容易过度思考。

如果你想更好地控制思考率，直接 prompt 它：

- 如果想要更多思考，尝试类似："在回答之前仔细一步一步地思考；这个问题比看起来更难。"
- 如果想要更少思考，尝试类似："优先快速响应而不是深入思考。不确定时，直接回应。"你会节省 token，但可能在更困难的步骤上失去一些准确性。

## 值得知道的行为变化

Opus 4.6 和 4.7 之间的一些默认行为发生了变化，如果你已经为旧模型仔细调整了 prompt 或 harness，值得了解：

1. **响应长度校准到任务复杂性**：Opus 4.7 不像 Opus 4.6 那样默认冗长。在简单查询上你可以期待更短的答案，在开放分析上更长的答案。如果你的用例依赖于特定长度或风格，在你的 prompt 中明确说明。我们发现你想要的声音的正面例子比负面的"不要这样做"指令效果更好。

2. **模型更少调用工具，更多推理**：这在许多情况下产生更好的结果。如果你想更多地使用工具（例如，在 agent 工作中更积极地搜索或文件阅读），提供明确描述何时以及为什么应该使用工具的指导。

3. **默认生成更少的 subagents**：Opus 4.7 对何时委托工作给 subagents 更谨慎。如果你的用例受益于并行 subagents（例如，跨文件或独立项目扇出），我们建议明确说明。例如："不要为你可以直接在一个响应中完成的工作生成 subagent（例如，重构你已经可以看到的函数）。当跨项目或读取多个文件扇出时，在同一 turn 中生成多个 subagents。"

## 接下来尝试什么

Opus 4.7 在长时间运行的任务上比之前的模型表现更好。这使其成为监督曾经是瓶颈的任务的良好选择，例如复杂的多文件更改、模糊的调试、跨服务的代码审查和多步 Agent 工作。

我们建议将 effort 保持在 xhigh，看看你的第一个 turn 能带你走多远。

## 我的总结与理解

### 核心变化

Opus 4.7 vs 4.6 主要变化：

1. **Tokenizer 更新**：影响 token 使用
2. **自适应思考**：不再固定预算，按需分配
3. **xhigh 新级别**：在 high 和 max 之间，推理和延迟的更好平衡
4. **默认更少冗长**：更精简的输出
5. **更少工具调用，更多推理**：产生更好的结果

### Effort 级别选择指南

| 级别 | 适用场景 | Token 使用 | 推荐程度 |
|------|----------|------------|----------|
| low/medium | 简单查询、成本敏感 | 最低 | ⭐⭐ |
| high | 并发 session、平衡质量成本 | 中等 | ⭐⭐⭐ |
| **xhigh（默认）** | 大多数编码和 Agent 任务 | 中高 | ⭐⭐⭐⭐⭐ |
| max | 真正困难的问题、非成本敏感 | 最高 | ⭐⭐⭐ |

### 交互式 vs 异步 Agent 的区别

- **异步（单用户 turn）**：更自主，token 使用更少
- **交互式（多用户 turn）**：用户每次输入后模型会额外推理，提高连贯性和质量，但消耗更多 token

### 最佳实践总结

1. **Upfront 详细描述任务**
   - 包含意图、约束、验收标准、文件位置
   - 避免在多个 turn 中逐渐补充

2. **减少用户 turn**
   - 批量问题，一次性给够上下文
   - 信任模型自主执行

3. **适时使用 Auto Mode**
   - 长任务 + 完全上下文 = 减少周期时间
   - Max 用户可用

4. **使用 xhigh 作为默认**
   - 智能和成本的最好平衡
   - 不需要 max 的过度思考

5. **控制思考深度**
   - 更多思考："这个问题比看起来更难"
   - 更少思考："优先快速响应而非深入思考"

### 对我们的启发

- [ ] 考虑将 xhigh 作为默认
- [ ] 自适应思考减少了调优需求
- [ ] 响应更精简，可能需要在 prompt 中明确风格
- [ ] 需要更多工具调用时，明确引导
- [ ] 需要更多并行 subagent 时，明确要求

### 一个核心原则

**把 Claude 当作能干的工程师委托，而不是配对程序员逐行指导**

- 第一个 turn 详细描述
- 减少中间干预
- 相信它的自主判断

---

**一句话总结**：Opus 4.7 是一个**更智能、更自律"的模型，需要更少的干预但需要更好的 upfront 任务描述**。
